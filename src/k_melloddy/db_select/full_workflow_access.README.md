# Full workflow access and extraction

Standalone official PMC table identity (2026-11-09): an unfinished complete HTTP-200 table response may contain the article title only in its Open Graph metadata. Recovery requires unchanged captured byte length/SHA256 (maximum 8 MiB), the same HTTPS official PMC table URL before and after redirects, the officially verified PMCID, exactly one matching og:title and og:url, an observed link back to that same article and exactly one link to the verified DOI. Title words must match; punctuation/case and PMC's optional leading "The" are normalized. Foreign hosts, changed identifiers, duplicate metadata, challenges, restricted or truncated responses fail. Original raw request caches and prior classification remain preserved; only the unfinished derived evidence changes and requires a fresh hash-bound review answer. No network request, article review, dataset count or inclusion is inferred. Standalone table content is still checked by the existing explicit HTML table parser. Resume through the existing workflow command. Offline validation: `python -m pytest tests/test_pmc_table_identity.py tests/test_typographic_identity.py tests/test_html_table_review.py tests/test_full_workflow.py tests/test_material_resume.py -q` (62 passed; exit code 0; existing Windows pytest temporary-directory cleanup PermissionError after success). Limits: official PMC standalone table pages only; DOI alone or a table caption alone is insufficient.

Translated-title identity recovery (2026-11-09): a PubMed title enclosed in one outer pair of square brackets may match the same complete title words in a captured article without that bibliographic wrapper. This additionally requires an already verified PMID match, the official DOI in the body, complete HTTP-200 bytes and the prior identity-only failure state. Inner brackets and title words are never removed or paraphrased. Output retains original bytes, metadata and prior failure classification; no request, full-text review attestation or final verdict is implied. Retry/resume reinterprets immutable cache bytes and creates a distinct evidence-bound review request; accepted historical answers remain unchanged. Units and limits follow the existing full-text contract. Tests: `python -m pytest tests/test_typographic_identity.py tests/test_full_workflow.py tests/test_material_resume.py -q` (21 passed), including wrong PMID, DOI, words and incomplete bytes. This does not recover translated titles with different wording or override access restrictions.

Complete captured metadata JSON may be served as binary/octet-stream by PMC's public cloud. A metadata-only recovery step validates byte length, SHA256, HTTP 200, complete response and actual JSON parsing before interpreting its text; original MIME, bytes and prior classification remain recorded. Metadata identity requires exact official PMID, PMCID and DOI plus normalized title; a mismatch remains identity_match=false. Invalid JSON, truncated bytes and restricted responses never gain access. Re-reading immutable cached bytes performs no new request and yields a distinct evidence-bound request if interpretation changes. It does not establish full-text review or dataset access. Tests: tests/test_binary_json_metadata.py, tests/test_archive_review.py, tests/test_material_resume.py and tests/test_full_workflow.py.

Inputs: official PMID/DOI/PMCID/title plus organ policy, prior pending code and observed URLs. Outputs: actual HTTP response records, source-linked text excerpts and bounded material samples. Units: requests, article passages, material rows/columns; none are paper inclusion counts.

Algorithm: extend independent legal-route discovery, follow observed publisher /pdf/ links, extract Methods/Results/Data Availability/repository context, request observed structured-material URLs and inspect CSV/TSV/JSON/XML/XLSX columns. PDF is an article, not a dataset. A parsed sample does not automatically establish licensing, toxicity relevance or reusability.

States/audit: accessible/access_restricted/fetch_error and response metadata keep their original meanings; unobserved facts stay unknown. Each completed URL request is stored in a round-specific immutable cache with SHA-256. File schemas and response errors are preserved. No access restrictions are bypassed.

Validation/retry/resume: official-identity gate and public-URL checks precede requests. Existing bounded retry policy applies. Restart reuses actual cached timestamps; a distinct deep round performs new requests. Only a reviewer can attest section meaning and final decisions. XML entities and malformed/inconsistent samples are rejected.

When a fulltext or observed PDF response exceeds the initial small metadata limit, one additional request group permits at most 8 MiB. The original truncated response remains a failure and the new response records `retry_of_evidence_id` and a `bounded_size_retry` route. PDF content-type detection also covers extensionless repository download URLs. This does not retry access restrictions or enlarge non-PDF dataset downloads. Cached previous evidence is never overwritten. Offline tests check the size cap, preservation, restored limits and absence of a size retry for HTTP 403.

Commands: used through `python -m k_melloddy.db_select.full_workflow ...`; no standalone collection command. Tests: tests/test_full_workflow.py checks structured JSON columns without a reusable-data claim; existing revalidation tests exercise CAPTCHA distinction, official identifier conflicts and alternative access. Limits: response size, at most eight new structured-file links per paper/pass, sample rows rather than full DB downloads, visual review required for scan-only articles.

The deep pass preserves initial evidence with reused_from_prior_round=true and original timestamps. It targets up to four failed article routes for P02, or known data/supplementary routes for the other P codes, then queries Crossref and follows observed identity-matched article links. Previously accessible article URLs are not retried solely because an earlier attempt failed. Reused requests are not counted as new HTTP attempts.

PMC page images are fetched only from observed article image links (up to 30 pages, 8 MiB each), recorded with source evidence IDs, URL, timestamp and content hash. Downloading images does not attest reading them; a session visual review must explicitly identify inspected pages. Metadata-only XML and abstract previews do not establish full-text review. Binary XLSX responses can be accepted as structured samples only after actual parsing succeeds.

New reviewer-observed discovery URLs added after the initial pass are also requested during the deep pass, without rewriting the initial evidence cache. Keep the discovery source and prior input version; a new URL is an access attempt, not a verified dataset. The offline regression checks that a new institutional PDF route is requested while an already successful discovery response retains its original evidence.

A reviewer-observed route added after an initial request is fetched into a separate immutable additional_discovery cache. Observed same-publisher PDF paths are also tested, without treating an HTML preview as a PDF. An initial supplemental bundle does not overwrite the original captured bundle.

On resume, an unfinished paper's old truncated HTTP-200 article/PDF checkpoint can receive a distinct `checkpoint_truncated_response_recovery` request (8 MiB maximum). The initial failure remains immutable, already successful URLs are skipped, and the recovery has its own request cache. This changes the evidence-bound review request; no previously completed verdict is silently rewritten.
# DOCX supplementary tables (2026-11-06)

ZIP data: complete public ZIP responses are inspected without extraction or code execution. At most 32 CSV/TSV/TXT members and 8 MiB of expanded table bytes are read. Mac metadata is ignored. Only one distinct table byte hash can supply columns; identical R/Python/Julia copies are audited separately but counted once. Multiple distinct tables and malformed rows require explicit review. Rectangularity is checked over all table rows; at most 100 data rows are exposed as a sample. Download recovery remains capped at 8 MiB for article/PDF responses and 32 MiB for other file responses, with distinct checkpoints. Completed 403 responses are never retried as size failures. Tests: tests/test_zip_material.py and tests/test_full_workflow.py. Scientific inclusion still requires an explicit evidence-bound review.

Typography recovery: unfinished complete HTTP 200 responses previously marked `article_identity_not_verified` can be reclassified only when the title matches after Unicode NFKC/dash normalization and the officially verified DOI is also in the text. Restricted, truncated, mismatched or DOI-free responses do not qualify. The original classification is retained in the derived evidence, immutable request cache remains unchanged, and a new evidence hash requires a fresh review answer. This verifies identity, not that the page contains the complete article. Test: tests/test_typographic_identity.py.

Complete HTTP 200 DOCX file responses are inspected as bounded ZIP/XML, including responses initially classified as empty decoded text. One rectangular, unmerged table with unique headers is recorded as `sample_structure`; up to 100 data rows are inspected. Actual headers, document text, table count and sample row count remain evidence, not automatic inclusion. Caption-level drug identity is not silently converted into a column. Multiple tables or merged headers require further review. HTML challenges, incomplete responses, unsafe XML and oversized document XML do not pass. Retries use existing request checkpoints; unfinished cached DOCX evidence is reinspected without replacing saved requests or finalized verdicts. Tests: `python -m pytest tests/test_docx_material.py tests/test_full_workflow.py -q`. No spreadsheet columns or scientific policy change.


XLSX inspection records the worksheet and header row. A single-cell caption followed by a complete header is retained separately and is not invented as a column. Missing/duplicate headers remain a structure limitation. tests/test_docx_material.py covers captions.

Downloaded XLSX files preserve a bounded raw-cell preview even when caption, duplicate or missing headers prevent structured-field verification. Opening a workbook proves file access only; columns and sample_structure are granted only after separate header checks. Pending requests re-inspect cached bytes and get a new evidence hash. tests/test_docx_material.py covers ambiguous headers without fabricated columns.
# Institutional PDF response recovery

Complete responses beginning with the PDF signature are parsed within the existing 8 MiB article bound even if the server labels them binary/octet-stream. Title and verified DOI must both match before access is accepted. Original MIME, transport classification and captured bytes remain auditable; truncated or mismatched PDFs do not pass. This only recovers readable evidence and never marks reviewer sections complete. Cached unfinished reviews are re-inspected without replacing immutable requests; resume creates a new evidence-bound request. Validation: tests/test_pdf_mime_recovery.py; existing workflow retry/resume tests. Unit: one HTTP evidence record. Commands and other workflow limitations below remain applicable.


### Complete multi-table ZIP evidence
Complete ZIP bytes containing several distinct tables are accessible material, not a transport failure. Each member and schema remain separate; no shared columns, eligibility or full-text review are inferred. Existing immutable caches remain preserved; unfinished review requests receive newly hashed interpretations. Truncated bytes remain unverified. Offline regression: tests/test_archive_access_state.py.

### Observed institutional download links
A reviewer-observed download can carry a Referer only when its exact URL was captured as a link on that page; cross-origin referers are rejected. HTTP evidence records the referer and caches use a distinct key. A complete PDF mislabeled HTML is parsed from magic bytes; title and official DOI must match (PDF DOI line breaks normalize as whitespace). No access success or full review is inferred from HTTP 200. Original attempts are preserved. Regression commands: pytest tests/test_observed_download_referer.py tests/test_pdf_mime_recovery.py.

Direct supplementary DOCX responses with complete ZIP bytes are interpreted as files while preserving original_kind and captured bytes. Their text and tables undergo the same checks as file routes; download success alone never establishes a common schema. Incomplete bodies remain supplementary. Regression: pytest tests/test_docx_material.py (6 passed).
# Resume inspection stability
Material inspection records a fingerprint of captured bytes, URL and MIME type. Repeating inspection of unchanged evidence returns the same derived content, so resumed requests do not accumulate duplicate sample text or invalidate review bindings. Original responses and prior artifacts remain immutable. Offline regression: `tests/test_material_resume.py`.


### Complete legacy XLS evidence
Complete OLE/BIFF .xls bytes are opened read-only with xlrd (declared dependency). The first sheet is bounded to 101 rows and 256 columns, with at most 64 sheets and 16 MiB input. Preserve raw response and original transport status. Only successfully opened raw cells establish access; unique complete headers establish sample_structure, not eligibility, full-file verification or a complete compound/label mapping. Truncated, HTML and invalid files remain unverified. Unfinished cached .xls records are re-inspected using a parser-specific fingerprint and receive a new immutable request hash; no repeat download is claimed. Tests: tests/test_material_resume.py. Live ten-paper run additionally opened the actual captured 1,656,320-byte CMap build02 XLS with 15 observed columns.


Complete supplementary PDF text inspection (2026-11-09): inspect_material reads at most 8 MiB, 64 pages and 250,000 extracted characters from an actual complete HTTP 200 PDF. Byte length, captured SHA256 and any known official checksum failure are checked first. Original bytes, URL, hash and request audit remain unchanged. Encrypted, invalid, truncated or over-limit documents do not gain reviewed text. Text is evidence for a reviewer, with response_sample level and no inferred columns, counts, dataset registration or reusable-data claim; image-only pages require separate visual review. PDF parsing performs no network requests and no embedded actions. A pdf-text-v1 inspection key causes unfinished cached materials to be reinterpreted without rewriting their original HTTP cache; finalized prior paper decisions are not rerun. Run via the existing full_workflow/batch resume commands.
