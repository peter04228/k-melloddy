# Dataset verification

Inputs: a schema-validated dataset proposal and immutable captured evidence. Outputs: a verified dataset with canonical identity, evidence hash, file format and observed verification level, or a validation exception. No network request, source edit or scientific decision is performed here. Counts are features/compounds only when actually measured by the collector; null counts remain unknown.

Algorithm/states: require accessible cited file/API evidence, an observed direct URL, verified structural level, actual endpoint/value columns, drug identity and independent-registration rationale. Bind the canonical dataset key to identity/version and retain citation/hash audit data. Landing pages and code repositories alone are insufficient. Validation failure blocks registration; it does not automatically exclude a paper. Retry/resume uses the same captured bytes. Existing decisions are not reclassified.

`drug_identifier` normally names an observed column. A single-agent clinical DOCX table may instead use `constant:NAME` only when NAME is present in the captured file's own caption before its first observed header and the dataset cites that exact caption from the same evidence. Patient IDs, article titles, unrelated evidence and arbitrary constants are insufficient. Endpoint and value fields must still be observed columns. The reviewer must establish that the caption exposure applies to the selected table and distinguish concomitant medications. No synthetic source column is added, and JSON/Excel schemas remain unchanged.

Command/tests: `python -m pytest tests/test_constant_drug_caption.py tests/test_docx_material.py tests/test_select.py tests/test_verified_select.py -q`. Tests cover cited constant exposure, wrong drug, absent caption, unsupported quotes, cross-file substitutions and invented value columns. Limitations: a caption identifies context; it does not certify causality or inclusion without the full workflow's independent evidence review. Only captions exposed as captured document text are eligible for the constant form.


## Explicit single-agent cohort context (2026-11-09)

For files without a drug column, an explicit reviewer-attested single-agent cohort may bind the constant exposure through the exact verified PMC article and its official cloud media metadata. It requires actual exposure/population citations, a rationale, exact file association, unchanged complete bytes and verified SHA256/official MD5; it never adds a drug column or changes observed values/labels. Dataset and workflow eligibility checks remain mandatory. Failed or mixed-cohort bindings stay unverified. Context and source references remain in JSON; existing finalized results are preserved and only unfinished review proposals are reevaluated on resume. Inputs/outputs/algorithm/states/units/audit/validation/retries/resume/commands/tests/limits: src/k_melloddy/db_select/dataset_context.README.md. Offline tests: tests/test_dataset_context.py plus existing dataset decision/full-workflow/resume tests.

Explicit single-agent cohort selection is supplied through evidence_review.single_agent_contexts, outside the frozen proposal schema. Exact selection, source article, official metadata, file hashes and cohort rationale are verified before a constant exposure can be accepted; no scientific column or label is generated. All input/output/algorithm/state/unit/audit/validation/retry/resume/command/test/limitation details are in dataset_context.README.md. Existing saved results and policy files remain unchanged.
