# Official PMC cloud discovery

Inputs: an already officially verified PMID/PMCID/DOI/title, the existing bounded public request interface, and prior captured records. Unverified identities trigger no requests. Execution lives in src/k_melloddy. The external LLM remains unconfigured; only the conversation reviewer can supply scientific decisions.

Algorithm: use PMC's documented public HTTPS ListObjectsV2 endpoint to discover the exact PMCID's version prefixes. For at most two versions, list at most 100 keys, then request only an actually listed metadata object. Check the metadata's own PMID, PMCID, DOI and normalized title. Never follow resource URLs from a mismatched record. Convert observed S3 resource URIs to the official bucket's HTTPS endpoint, require the verified article-version path and a metadata-provided MD5, and compare complete response bytes against both captured SHA256 and the metadata MD5. Fetch article XML when no readable verified body was captured, and at most three relevant supplementary objects across matched versions. A version number does not establish recency; version/manuscript/license/retraction metadata and any limits remain explicit for the reviewer. Images are not downloaded by this helper.

Outputs and units: additional immutable request records and search coverage, measured in request attempts, article versions and file objects. These are never paper counts or dataset counts. No fulltext_reviewed, included/excluded verdict, dataset registration or structure meaning is inferred. A complete checked binary file can be accessible while its structure is still unknown. Empty or malformed listings, missing metadata, identity/checksum mismatches and reached limits are recorded as unresolved; they do not prove that research data do not exist.

States/audit: attempted, version/object lookup failure, metadata identity unverified, investigated, or metadata/inspection error. Keep URLs, HTTP status, original MIME, actual bytes, timestamps, SHA256, observed S3 URI, expected/observed MD5, and interpretation changes. Cloud XML must match the article's own identifiers; references to another article never qualify. A recovered binary JSON/XML response retains the original capture and records the interpretation separately. ZIP access alone cannot establish reusable data; explicit bounded member/sheet/header inspection and actual source review are still required. No archive is extracted or executed.

Retries/resume: use the existing request timeouts, size limits, public-address checks and bounded retries. A separate per-paper/per-round pmc_cloud_2026_v1 checkpoint retains only the additional evidence. Resuming the same round reuses actual responses without claiming new requests. Deep revalidation receives a distinct round checkpoint. Prior finalized paper records and published workbooks are skipped by the existing workflow and are not silently rewritten. Interrupted publication still resumes from SQLite and hashes.

Commands: the regular batch_workflow/full_workflow execution commands invoke this discovery only when a real FullWorkflowAccess collector has an official PMCID. Real retrieval is authorized through the existing explicit research run; offline fixtures never invoke network discovery. Tests: python -m pytest tests/test_pmc_cloud.py tests/test_full_workflow.py tests/test_prior_evidence_merge.py tests/test_binary_json_metadata.py. Tests cover observed-key discovery, identifier mismatches, generic binary JSON/XML, MD5 failures, unverified input, foreign paths, traversal and absent checksums, with synthetic public responses. No research outcomes are generated by tests.

Limitations: current metadata requires a verified DOI as well as PMID/PMCID/title. Some article versions contain no supplementary objects or have license limitations; a lookup or file absence is not a scientific exclusion. Only two versions, 100 listing keys and three relevant materials are inspected. S3 listing truncation and omitted versions/materials stay visible. XLS/HDF/PDF content may still need explicit reviewer inspection. This helper does not revisit already terminal P papers automatically or implement DB_Download/DB_Preprocessing.

Official technical references consulted 2026-11-08: https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/ and https://pmc-oa-opendata.s3.amazonaws.com/README.txt. PMC's retired OA Web Service is not used.
