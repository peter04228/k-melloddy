# Explicit archive table review

Explicit DOCX selections can opt into `include_preceding_paragraph: true` to preserve the actual paragraph immediately before the selected table as citable exposure context. The exact parsed table object determines the context even when multiple tables have identical cells. No drug column is created, and a missing/blank preceding paragraph fails validation. Derived IDs include the explicit selection; original records, bytes, finalized answers and default selections remain unchanged. Existing caption validation still requires a same-record quote containing the named constant and real endpoint/value columns. Units, retry/resume and audit behavior follow the selection contract below. Offline verification: `python -m pytest tests/test_docx_material.py tests/test_constant_drug_caption.py tests/test_archive_review.py -q` (31 passed). Context is evidence for reviewer interpretation, not automatic proof of causality or dataset eligibility.

Inputs: captured complete public file evidence, its hash, and an explicit reviewer selection of archive members, sheet and header row. Outputs: a derived evidence record with parent ID, per-member hashes, raw observed headers and sampled cells. No remote request or file execution occurs.

The algorithm opens ZIP magic bytes (including misnamed TGZ containers) in memory, traverses at most three exact members, and reads one explicitly selected XLSX or legacy XLS sheet. XLS requires OLE magic bytes and xlrd, at most 64 sheets, and an explicitly named sheet/header row. Limits: 32 MiB container, 16 MiB member, 1000 members, 64 MiB XLSX expansion, 256 columns and 101 inspected rows. Duplicate/missing member names, ambiguous headers, unlabelled populated columns and formula strings fail closed. No archive member is extracted to disk or code executed. XLS uses stored cell values and does not recalculate or certify workbook formulas. General TAR is unsupported. The derived MIME identifies the actual selected workbook; parent HTTP content-type and source bytes are preserved.

States: verified sample structure or review validation failure. Units are archive bytes, table rows and columns; neither sample rows nor sheet extent is promoted to compound counts. HTTP fields refer to the captured parent; `request_performed: false` prevents interpreting derived evidence as a new request. The original evidence is unchanged. An explicit accepted answer stores selection and hashes in the normal append-only evidence document.

Retry/resume: selections deterministically re-read existing immutable bytes, requiring no download. Correct a rejected unconsumed review with the documented answer workflow; consumed reviews remain preserved. Run the normal spreadsheet_workflow command to resume. Tests: `python -m pytest tests/test_archive_review.py -q`. Eligibility, endpoint meaning and independence still require the reviewer; no automatic inclusion follows parsing.

2026-11-09 integrity rule: a captured parent with `cloud_checksum.verified: false` is rejected before archive inspection, even when its local SHA-256 and complete HTTP bytes agree. An explicit selection cannot override a failed official PMC MD5. Unknown checksum metadata retains the existing complete-byte checks; successful parsing alone never verifies provenance. The regression test covers rejection, unchanged parent records and the verified-checksum path. This applies to newly evaluated evidence and does not rewrite finalized research records.

## Explicit DOCX table selection
Input evidence_review.docx_selections binds parent_evidence_id, zero-based table_index and optional exclusive row_end (starting at header row zero). Output is a derived sample_structure record with exact observed headers, parent bytes/hash and selected sample. No column is synthesized and no HTTP request is claimed. Complete accessible file bytes and SHA-256 must validate; XML is bounded to 8 MiB and entity declarations are rejected. Duplicate/blank headers, merged selected cells, irregular widths and out-of-range selection fail. Explicit row bounds may exclude a merged footer without altering source bytes; reviewer must explain that scope. Repeating a selection is idempotent; corrected choices produce a new evidence-bound answer. Units are tables and sampled rows, not dataset/compound counts. Free-text exposure fields still require reviewed case context. Tests: pytest tests/test_docx_material.py tests/test_archive_review.py. Limitations: no automatic contextual drug-column creation, merged-cell filling or normalization.


2026-11-09 explicit direct workbook selection: archive_selections may use an empty members list to select a named sheet and header row directly from a captured complete XLSX/XLS. This makes no request, invents no columns and preserves parent bytes/hash; derived transport is workbook_sheet with accurate workbook_inspection/workbook_preview. Direct workbooks are limited to 16 MiB, with existing sheet/column/expansion/formula checks. Incomplete bytes and known failed official checksums are rejected. Non-empty archive chains retain existing behavior. Related offline group: 39 passed, exit 0 (existing nonfatal Windows pytest temp cleanup warning after tests). Finalized records remain unchanged.
# DOCX inside a supplementary ZIP

Explicit `docx_selections` may include a `members` chain (at most three exact archive members) before the existing `table_index` / optional `row_end` selection. This inspects already captured bytes only; it performs no network request and preserves the original ZIP evidence. Member uniqueness, compressed input bounds, member expansion bounds, XML safety, checksum failures, merged cells and actual headers remain validation gates. Derived DOCX hashes and archive member names are retained alongside the parent URL and request metadata. Structure verification alone never establishes inclusion, independent data or numerical counts. Direct DOCX selections remain compatible. Retry/resume reuses immutable source bytes and deterministic selection IDs. Tests: `tests/test_docx_material.py` and `tests/test_archive_review.py`.

## CSV inside a supplementary ZIP

An explicit `archive_selections` entry may name an exact `.csv` member with `sheet: null` and a one-based `header_row`. The same parent-byte, checksum, member and expansion checks apply. UTF-8 (optional BOM) is decoded strictly; comma-separated quoted fields are parsed without executing formulas. At most 101 rows from the chosen header are inspected, with at most 256 columns. Irregular widths, blank/duplicate headers, malformed quoting, non-UTF-8 bytes, formulas and a fabricated worksheet name fail validation. Actual headers, sampled values and member SHA-256 are preserved; no columns or join keys are added. No HTTP request occurs. Retry/resume deterministically reuses captured bytes. Tests: `python -m pytest tests/test_archive_review.py -q`. This verifies sample structure only, not all rows, cross-file joins or compound counts; reviewers must evaluate those separately.
