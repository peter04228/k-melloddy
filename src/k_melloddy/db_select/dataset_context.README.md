# Single-agent cohort material binding

Inputs: a reviewer-declared constant exposure, exact exposure/population citations from one complete identity-verified official PMC article, the official PMC cloud metadata response and its actual public file. Output: a dataset context audit with binding_verified and source PMCID; original file columns, values, labels and bytes remain unchanged. Algorithm: verify exact citations, drug words, reviewer rationale, official article/metadata association, all four verified metadata identity checks, exact media_urls entry, actual URL and complete payload length/SHA256 plus official MD5. No exposure column or scientific value is generated. States: absent context uses the existing column/file-caption contract; failed binding raises a validation error; successful binding verifies contextual identity only, and all existing endpoint, structure, independence and workflow requirements still apply. Units: one dataset file/cohort binding, with 1 MiB metadata and 16 MiB file bounds. Audit: the full cited context remains in screening JSON, with immutable source evidence and prior proposals preserved. Retries/resume reinterpret only unfinished proposals; finalized datasets and ledger events are not rewritten. Commands: use the existing batch resume command; offline tests: python -m pytest tests/test_dataset_context.py tests/test_select.py tests/test_full_workflow.py tests/test_material_resume.py -q (test-file availability is checked when running). Limitations: explicit single-agent cohort only; mixed-agent datasets need actual row-level identifiers; only exact official PMC article/cloud media association is supported. This does not resolve mortality label discrepancies, infer toxicity causality, calculate dataset counts or convert data. Source bibliography and the reviewer must establish cohort semantics; transport/link verification alone never confirms inclusion.

Interface: the explicit binding is submitted in evidence_review.single_agent_contexts as {evidence_id, drug_identifier, context}. It is not added to the frozen proposal schema or organ policy. SessionProvider preserves the selection; the dataset verifier accepts exactly one matching selection and validates it before adding the verified drug_context audit to the finalized dataset. This keeps the active policy hash stable and leaves historical proposals unchanged.
