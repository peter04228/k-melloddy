# Explicit article HTML table review

Explicit public PMC table files: when a selection's parent is an actual `file` response, the caller must also pass the officially verified paper. The parser verifies captured complete HTTP-200 bytes, the exact official PMC standalone-table URL, PMCID, matching article title/DOI and parent link with the existing strict metadata binder. Only the derived table receives this identity binding; the original file kind, status, bytes and failed attempts remain unchanged. This does not mark the full article reviewed. Non-PMC files, missing official verification, mismatched/duplicate metadata, wrong identifiers, failed checksums and changed bytes fail closed. The usual header-span and unmerged-data checks still apply; combination strings and causality levels remain as printed. Resume is deterministic and makes no request. Tests: `python -m pytest tests/test_http_material_capture.py tests/test_pmc_table_identity.py tests/test_html_table_review.py tests/test_full_workflow.py -q`.

Inputs: an evidence-bound session answer's `evidence_review.html_table_selections`, containing `parent_evidence_id` and zero-based `table_index` across captured HTML tables. The parent must be a complete accessible HTTP-200 identity-verified article with unchanged bytes/length/SHA-256; any known failed official checksum rejects it. No download is performed.

Outputs/algorithm: a derived `kind: file`, `transport: html_table`, `sample_structure` record binds the original source kind, bytes, URL, hash and explicit selection. Actual header cells and their declared spans are preserved. Header row/column spans form a complete rectangular grid; unique nonempty bottom-level labels become columns. Body rows must already have exactly that width and contain no merged cells. Five actual rows are sampled; no values, drug IDs, row IDs, units, labels or scientific counts are invented. Original header groups remain available for interpretation (e.g. peak versus initial values).

States/units/audit: success verifies sample structure only; failure blocks the reviewer answer. Units are captured bytes, table indices, header spans and sample rows/cells. `request_performed: false` and the parent evidence ID distinguish derivation from HTTP acquisition. `downloaded_full_dataset: false` avoids claiming an independent raw-data download. A selected paper table can contain reusable observations, but scientific relevance, independence and interpretation still require explicit review and citations; parsing never includes a paper automatically.

Validation/limits: UTF-8 HTML, 8 MiB source, 64 tables, 8 header rows, 256 columns, 5,000 body rows, declared spans 1–64. Nested, unclosed, irregular, blank/duplicate headers, incomplete/overlapping header grids and merged data rows fail. Explicit thead/tbody are required. No scripts execute, OCR, fuzzy matching, body-cell filling, title changes or cross-table joins occur. This does not parse JATS XML or normalize a rotated PDF.

Retry/resume: deterministic selection IDs reuse immutable source bytes; a corrected unconsumed answer gets a new selection/evidence binding. Finalized records and source values remain unchanged. Command: resume the normal `python -m k_melloddy.db_select.batch_workflow ...` with the request-bound answer. Tests: `python -m pytest tests/test_html_table_review.py tests/test_full_workflow.py -q`; they verify spans, exact values including missing strings, source preservation/idempotence, dataset-field checks, malformed structure, source identity/access/hash failures and existing session behavior. Limitations include image tables, missing explicit table sections, merged data and general clinical causality interpretation.
