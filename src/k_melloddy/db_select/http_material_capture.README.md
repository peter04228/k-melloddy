# Reviewed public GET material receipts

Inputs: `public_http_captures` in a paper's explicit session-review entry. Each item specifies a run-relative immutable JSON path and its SHA-256. The JSON contains `paper_id`, `pmid`, a nonempty `reviewer_note` and the actual captured HTTP `record`. Keep the original successful receipt and the native failed attempts. This import is reviewer-attested reuse of a real response, not a new request or a server-signed proof.

Algorithm: check run-path containment, wrapper size/hash and matching paper/PMID; require an accessible public GET file/API receipt with actual HTTP 200, timestamp, complete nonempty bytes and matching length/SHA-256. Its same-role URL must already occur in the native collector evidence. Reject authenticated/POST/web-excerpt/error receipts, private literal addresses and credential URLs. No DNS lookup or network request occurs during import. Retain original bytes/status/timestamp/URL and source evidence ID under a stable wrapper-derived evidence ID; retain the wrapper path/hash and reviewer note. Reset schema claims to `response_sample`, empty columns and `downloaded_full_dataset: false`; actual structure and scientific eligibility still need separate verification.

Outputs/states: append a validated evidence record, leaving original receipts and failed collector records unchanged. Invalid receipts stop the unfinished review rather than generating an exclusion or inclusion. Units/limits: at most three receipts per paper, 16 MiB per JSON wrapper and 8 MiB per complete response body. Row, feature and compound counts are not generated.

Audit/retries/resume: original evidence ID, capture hash/path, bytes/hash, actual response timestamp and explicit reviewer note remain linked. `source_request_performed: true` refers to the original captured request; `request_performed: false` means this import made none. Reusing the same wrapper produces the same ID without duplicates. A native retry returning CAPTCHA does not erase a previously successful receipt. Corrected wrappers use new immutable paths/hashes; never edit a prior wrapper, finalized decision or ledger event.

Commands: resume the existing batch through `run_batches` or the documented CLI/session workflow; no separate live collection command is introduced. Tests: `python -m pytest tests/test_http_material_capture.py tests/test_pmc_table_identity.py tests/test_html_table_review.py tests/test_full_workflow.py tests/test_verified_select.py tests/test_revalidation_campaign.py tests/test_select_stabilization.py -q`. Fixtures check stable reuse, preserved failures/bytes/combination strings/causality values, absent automatic schema claims, scope/hash/identity/method/access failures and strict PMC article binding. Limitations: only already observed public file/API routes; no web excerpts as dataset downloads, login/paywall/CAPTCHA bypass, automatic scientific verdict, or arbitrary local file registration.
