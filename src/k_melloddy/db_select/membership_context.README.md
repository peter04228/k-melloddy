# Published column-membership verification

Inputs: an explicitly reviewed `evidence_review.column_memberships` entry naming the derived workbook evidence ID and a `context`. The context declares `scope: column_membership_list`, a reviewer rationale, the one actual `member_column`, an exposure `metadata_evidence_id`, its actual worksheet/key/drug/context field names, one exact metadata filter, and cited official manifest/classification references. The material must already have an explicit worksheet/column selection. This mode represents a category named by the original column heading whose cells list existing experiment/condition identifiers; it does not fabricate Drug, Endpoint or Value columns.

Algorithm: verify the complete identity-checked official PMC version manifest and the same article's classification citation; bind both workbooks through exact listed URLs and official MD5. Validate original complete HTTP-200 bodies, length/SHA-256 and checksum flags. Reopen original XLSX bytes read-only. Check the unique actual selected header, all category members, contiguous nonempty entries followed only by empty trailing cells, uniqueness and absence of formulas. Match each existing member key to the declared filtered exposure metadata and require exactly one distinct tuple of the actual drug/context values; repeated identical biological-replicate metadata is allowed. Copy these original values into a verification audit without writing a joined or transformed dataset.

Outputs/states/units: `membership_context` on the verified registration retains the original column, member count actually checked, original member IDs, exact source-value bindings, binding hash, filter, references and rationale. A member count is a number of listed experimental conditions, not a compound/patient count. This verifies data structure/provenance only; study purpose, organ relevance, computational versus observed labels and independent publication still require the ordinary full-text decision. The original file, raw column names, source values and disease labels remain unchanged. A computational category is not automatically a clinical DILI, causality or safety label; kidney-only categories must not be described as liver toxicity.

Bounds/validation: two actual XLSX files, each at most 16 MiB compressed/64 MiB expanded; category worksheet at most 5,001 rows and 1,024 columns; exposure worksheet at most 50,001 rows and 256 columns; at most eight declared exposure fields. Reject missing/duplicate headers, empty/duplicated/gapped/formula identifiers, unlisted files, wrong article/checksums, missing or ambiguous exposure matches and substituted column names. Exact filter values and units are retained; no dose conversion, cluster inference, label assignment or graph digitization occurs.

Audit/retries/resume: deterministic offline inspection of immutable captured bytes; no request, new source record or dataset rewrite. The proof and actual source references are retained in SQLite/JSON and the ordinary registration description/URL reaches the existing Excel columns. Invalid contexts leave the unfinished review for correction rather than changing a scientific verdict. Repeated verification yields the same bindings/hash. Finalized registrations and ledger events are not rewritten. Legacy ordinary-column/caption/single-agent paths retain their existing contracts; this extra mode activates only when explicitly declared (or when rechecking an existing membership proof).

Commands/tests: use the existing batch resume command and a hash-bound session answer; no collection command or external LLM configuration is added. `python -m pytest tests/test_membership_context.py tests/test_dataset_context.py tests/test_full_workflow.py tests/test_verified_select.py tests/test_revalidation_campaign.py tests/test_select_stabilization.py -q`. Real XLSX fixtures check exact source values, retained original columns/bytes, organ filtering, replicate duplicates, deterministic resume and rejected unmatched/ambiguous/formula data, missing context, identity/hash/checksum/manifest substitutions. Limitations: explicitly selected one-column lists and official PMC-listed exposure workbooks only; no generic relational join, preprocessing output, inferred compounds or inferred scientific counts.
